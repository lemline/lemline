Fan-out and fan-in

Fan-out distributes work. Fan-in brings the results together. The DSL has several ways to model these patterns, depending on where the work happens.

Run independent branches

A fork starts its branches concurrently. A non-competing fork joins their results after all branches finish. Start the tutorial shop and supply {"orderId":"QUOTE-1"} to request the stock level and a shipping quote.

document: dsl: '1.0.3' namespace: examples name: parallel-order-checks version: '1.0.0' do: - checkOrder: fork: branches: - checkStock: call: http with: method: get endpoint: http://127.0.0.1:8787/stock output: as: '${ { available: .available } }' - checkShipping: call: http with: method: post endpoint: http://127.0.0.1:8787/quotes/express body: ${ . } output: as: '${ { checks: . } }'

Iterate over input data

A for task runs its body for each item of a collection. Bind the current value with each and its index with at.

document: dsl: '1.0.3' namespace: examples name: map-order-items version: '1.0.0' do: - calculateTotals: for: each: item in: ${ .items } at: index do: - calculateLine: set: itemId: ${ $item.id } index: ${ $index } lineTotal: ${ $item.quantity * $item.price }

Collect results from independent services

If outside services publish events, use listen.to.all to require every event type. Use correlation to scope matches to the current workflow instance.

document: dsl: '1.0.3' namespace: examples name: listen-for-all-results version: '1.0.0' do: - collectResults: listen: to: all: - with: type: com.example.inventory.checked - with: type: com.example.shipping.quoted timeout: after: PT5M - recordResults: set: checks: ${ . }

Recover when a branch fails

Use try around the fork for a group-wide fallback. To recover inside a specific branch, place the handler in that branch.

document: dsl: '1.0.3' namespace: examples name: parallel-checks-with-fallback version: '1.0.0' do: - attemptChecks: try: - checkOrder: fork: branches: - inventory: call: http with: method: get endpoint: http://127.0.0.1:8787/stock query: fail: '503' failTimes: ${ .inventoryFailures // 0 | tostring } key: ${ .orderId } - shipping: call: http with: method: post endpoint: http://127.0.0.1:8787/quotes/express body: orderId: ${ .orderId } catch: do: - requestManualReview: set: status: needs-review

Run the Examples

Every example on this page is a complete workflow. Complete the SQLite setup, save each example under the file name used below, and run the commands from the setup directory. With the JAR, substitute java -jar lemline.jar for bin/lemline.

Start the tutorial shop from the root of the Lemline source checkout:

docker compose -f examples/tutorial-services/compose.yaml up -d

The event examples need the tutorial publisher. Save it as tutorial-publisher.yaml:

document: dsl: '1.0.3' namespace: examples name: tutorial-publisher version: '1.0.0' do: - publish: emit: event: with: type: ${ .type } source: https://events.example.com/tutorial data: ${ .data }

Keep the setup worker running and use a second terminal in the setup directory.

bin/lemline definition post -f tutorial-publisher.yaml bin/lemline definition post -f parallel-order-checks.yaml bin/lemline instance start examples parallel-order-checks --input '{"orderId":"QUOTE-1"}' bin/lemline definition post -f map-order-items.yaml bin/lemline instance start examples map-order-items --input '{"items":[{"id":"SKU-1","quantity":2,"price":25},{"id":"SKU-2","quantity":1,"price":12}]}' bin/lemline definition post -f listen-for-all-results.yaml bin/lemline instance start examples listen-for-all-results bin/lemline instance start examples tutorial-publisher --input '{"type":"com.example.inventory.checked","data":{"stock":2}}' bin/lemline instance start examples tutorial-publisher --input '{"type":"com.example.shipping.quoted","data":{"price":15}}' bin/lemline definition post -f parallel-checks-with-fallback.yaml bin/lemline instance start examples parallel-checks-with-fallback --input '{"orderId":"QUOTE-3","inventoryFailures":1}'
