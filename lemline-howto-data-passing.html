How to pass data between tasks

By default, the transformed output of one task becomes the input of the next task. Use input.from when a task needs to select or reshape its input, and output.as when a task needs to adapt its result for the following step.

Shape input and output

The workflow below transforms its input, calculates a result and returns selected fields in its output.

Complete the SQLite setup and keep its worker running. Run the commands from a second terminal in the setup directory. With the JAR, substitute java -jar lemline.jar for bin/lemline. Save the definition as transform-workflow-data.yaml:

document: dsl: '1.0.3' namespace: examples name: transform-workflow-data version: '1.0.0' input: from: '${ { customer: .user, items: .payload.items } }' do: - summarize: set: customerId: ${ .customer.id } itemCount: ${ .items | length } output: as: '${ { customerId, itemCount } }'
bin/lemline definition post -f transform-workflow-data.yaml bin/lemline instance start examples transform-workflow-data --input '{"user":{"id":"C-100","name":"Ada Lovelace"},"payload":{"items":[{"id":"SKU-1"},{"id":"SKU-2"}]}}'

The workflow-level input.from keeps only customer and items, the task counts the items, and output.as keeps two fields: expect {"customerId":"C-100","itemCount":2}.

Share a value across tasks

Use export.as to update $context. Merge the new value with the existing context when earlier context entries must remain accessible. Use $workflow.input to read values supplied when the workflow started.

document: dsl: '1.0.3' namespace: examples name: share-order-context version: '1.0.0' do: - identifyCustomer: set: customerId: ${ .customer.id } export: as: '${ $context + { customerId: .customerId } }' - prepareOrder: set: orderId: ${ $workflow.input.orderId } customerId: ${ $context.customerId }

Save it as share-order-context.yaml:

bin/lemline definition post -f share-order-context.yaml bin/lemline instance start examples share-order-context --input '{"orderId":"ORD-803","customer":{"id":"C-100"}}'

The second task reads the customer from $context and the order ID from $workflow.input: expect {"orderId":"ORD-803","customerId":"C-100"}.
