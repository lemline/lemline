How to jump between tasks (then, exit, end)

Tasks run in the order listed in do. Use a flow directive to override that order.

Directive

Effect

continue

Advance to the next task in the current list

Task name

Move to the named task in the current list

exit

Leave the current task list and return to its parent

end

End the workflow

Select a task with switch

Each named case has a then directive. The first case whose when condition matches wins. A final case without a condition provides a fallback.

Complete the SQLite setup and keep its worker running. Run the commands from a second terminal in the setup directory. With the JAR, substitute java -jar lemline.jar for bin/lemline. The worker logs Workflow completed with output with each result. Save each definition under the file name used in its definition post command.

document: dsl: '1.0.3' namespace: examples name: validate-and-route-order version: '1.0.0' input: schema: format: json document: type: object required: [orderId, total] properties: orderId: type: string total: type: number minimum: 0 do: - routeOrder: switch: - largeOrder: when: ${ .total >= 1000 } then: requestReview - automatic: then: acceptOrder - requestReview: set: status: needs-review then: exit - acceptOrder: set: status: accepted output: as: '${ { orderId: $workflow.input.orderId, status: .status } }'
bin/lemline definition post -f validate-and-route-order.yaml bin/lemline instance start examples validate-and-route-order --input '{"orderId":"ORD-301","total":250}' bin/lemline instance start examples validate-and-route-order --input '{"orderId":"ORD-302","total":1500}'

Expect {"orderId":"ORD-301","status":"accepted"} and {"orderId":"ORD-302","status":"needs-review"}.

After setting its status, the manual-review path uses then: exit to leave the task list instead of falling through to the automatic path. The workflow's output.as still runs, as it does after then: end.

Exit a nested task list

Here a missing order ID exits the inner do list. The outer list resumes at finalize.

document: dsl: '1.0.3' namespace: examples name: exit-nested-scope version: '1.0.0' do: - processOrder: do: - checkOrder: switch: - invalid: when: ${ .orderId == null } then: exit - valid: then: recordOrder - recordOrder: set: status: received - finalize: set: completed: true status: ${ .status // "skipped" }
bin/lemline definition post -f exit-nested-scope.yaml bin/lemline instance start examples exit-nested-scope --input '{"orderId":"ORD-1"}' bin/lemline instance start examples exit-nested-scope

With an order ID, recordOrder runs and the result is {"completed":true,"status":"received"}. Without one, the inner list exits before recordOrder and the result is {"completed":true,"status":"skipped"}.
