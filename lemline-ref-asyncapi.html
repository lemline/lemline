AsyncAPI Reference

This page describes the support of call: asyncapi tasks in Lemline.

AsyncAPI Support Status

Lemline does not execute call: asyncapi tasks yet. The Open Workflow DSL defines them (see AsyncAPI calls), and Lemline parses workflows that contain them, but no runner can run such a task: do not use it in workflows you deploy.

There are no lemline.asyncapi.* runner settings.

Alternative

Exchange messages as CloudEvents with emit and listen tasks. They travel on the broker Lemline is configured with (see Message Brokers):

document: dsl: 1.0.3 namespace: examples name: asyncapi-alternative version: 1.0.0 do: - publishOrder: emit: event: with: type: com.example.order.created source: https://events.example.com/order-service data: ${ .order } - waitForPayment: listen: to: one: with: type: com.example.payment.received

Run the Examples

Every example on this page is a complete workflow. Complete the SQLite setup, save each example under the file name used below, and run the commands from the setup directory. With the JAR, substitute java -jar lemline.jar for bin/lemline.

The event examples need the tutorial publisher. Save it as tutorial-publisher.yaml:

document: dsl: '1.0.3' namespace: examples name: tutorial-publisher version: '1.0.0' do: - publish: emit: event: with: type: ${ .type } source: https://events.example.com/tutorial data: ${ .data }

Keep the setup worker running and use a second terminal in the setup directory.

bin/lemline definition post -f tutorial-publisher.yaml bin/lemline definition post -f alternative.yaml bin/lemline instance start examples asyncapi-alternative --input '{"order":{"orderId":"ORD-1701"}}' bin/lemline instance start examples tutorial-publisher --input '{"type":"com.example.payment.received","data":{"orderId":"ORD-1701"}}'
